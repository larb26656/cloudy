# Plan: Backend workspace feature with SQLite (inline DB)

## Why

Workspace data today lives only in the frontend (`apps/web-app/src/stores/workspaceStore.ts`,
Zustand + localStorage) — it is never sent to the server, so it cannot survive a browser
wipe, sync across devices, or back any future server-side feature that keys off workspace.
At the same time the existing `packages/database` package (PGlite/WASM Postgres) is dormant:
no runtime wiring, only a broken test fixture imports it. We want to (a) collapse
`packages/database` into `packages/server`, (b) swap PGlite → SQLite (`better-sqlite3`,
sync), and (c) ship a `workspaces` CRUD feature that becomes the new source of truth. This
plan covers backend only; the frontend migration to React Query is a follow-up plan.

## Context the new session needs

- **Repo conventions** (root `AGENTS.md`): ESM only; `import type` for type-only imports;
  `noUncheckedIndexedAccess` on; no comments unless asked; camelCase vars / PascalCase
  types; Zod for DTOs (no hand-written parallel types); Prettier default config.
- **Backend feature layout** (root `AGENTS.md` "Backend conventions" + the canonical example
  shipped by `docs/plan/20260802-server-3tier-refactor.md`): `features/<feature>/<feature>.*.ts`.
  Read `packages/server/src/features/pty/` first — it is the only feature with the full
  controller/service/repository/model/errors/test layout. Copy its style verbatim.
- **DI style: factory functions, no classes.** `createXxxRepository(db)` returns a plain
  object of methods; `createXxxService(repo)` same; `createXxxController(service)` returns a
  `new Hono()`. See `packages/server/src/container.ts:11` and
  `packages/server/src/features/pty/in-memory-pty.repository.ts:40`.
- **Dependency rule (must preserve):** controller imports service (type) + hono. Service
  imports the repository interface + model + errors. **Never** import `hono`, `ws`,
  `node-pty`, or `drizzle` from a service. Repository impl owns infra. Documented in
  `docs/plan/20260802-server-3tier-refactor.md:60-72`.
- **Error model:** services throw `DomainError` subclasses from
  `packages/server/src/shared/domain-error.ts:11-54` (`NotFoundError`, `ConflictError`,
  etc.). The Hono middleware at `packages/server/src/presentation/error-middleware.ts:16-29`
  catches them and maps to HTTP status. **Never** throw `HTTPException` from a service —
  that contradicts the post-refactor rule even though root `AGENTS.md` still mentions
  `HTTPException` (the AGENTS.md text is stale on this point; trust the refactor plan).
- **Validation:** `zValidator("json", schema)` from `@hono/zod-validator` +
  `describeRoute({...})` from `hono-openapi`. See `packages/server/src/features/pty/pty.controller.ts:3,27,71`.
- **Config layered merge:** defaults → `~/.config/cloudy/config.json` → `CLOUDY_*` env →
  CLI flags. Schemas + env name map at `packages/server/src/config/config.ts:6-39`. Add
  `dbPath` with default `~/.config/cloudy/data/sqlite` and env `CLOUDY_DB_PATH`. `~` is
  expanded via `expanduser` (`config.ts:20-26,84`).
- **Container is currently sync.** Keep it sync — `better-sqlite3` is sync, so no `await`
  needed and `packages/server/src/server/createServer.ts:37` does not change.
- **Migrations path resolution:** both `migrate.ts` and `test-utils.ts` resolve the
  migrations folder as `join(dirname(fileURLToPath(import.meta.url)), "../../drizzle")`.
  After the move, `__dirname` is `packages/server/dist/db/` (compiled) — `../../drizzle`
  lands at `packages/server/dist/drizzle/`. Confirm the `copy-assets.ts` flow still
  copies `packages/server/drizzle/` → `apps/server/dist/drizzle/` so bundled runtime finds
  it. Same strategy the existing PGlite code uses (see
  `packages/database/src/migrate.ts:26-27`).
- **DB schema decisions (already made, do not revisit):**
  - SQLite only via `better-sqlite3` (native binding, sync, Node 18+ compatible).
  - Timestamps: `integer("created_at", { mode: "timestamp" })` with
    `.default(sql\`(unixepoch())\`)` — Drizzle maps to JS `Date`.
  - No arrays in SQLite. Workspaces table has no `tags` column by design.
  - `directory` is `text NOT NULL UNIQUE` — mirrors frontend dup-check semantics
    (`workspaceStore.ts:58-66`).
- **Drop `instanceId`.** Frontend `Workspace.instanceId` is a dead field (always
  `"default"`); do not add it to the schema or DTO.
- **`@repo/contracts` re-exports `AppType` type-only** (`packages/contracts/src/index.ts:40`).
  Adding the workspaces route to `server.ts` automatically extends the contract — no edit
  needed in contracts.
- **Story files use `packages/database/...` as cosmetic fixture strings** (file paths in
  mock data, not real imports). Update them so they don't reference a deleted path.
- **Do not touch** `docs/adr/*` or existing `docs/plan/*` files — they are immutable
  historical records.

## Notes for implementer

- **better-sqlite3 is a native module.** `pnpm install` will trigger a build via node-gyp
  if no prebuilt binary matches your Node version. Ensure Xcode CLT (macOS) is installed.
  If the install fails on native compile, fall back to a `--build-from-source=false`
  prebuilt fetch.
- **Sync API throughout.** `better-sqlite3` and `drizzle-orm/better-sqlite3` are sync.
  Repository methods return plain values (not Promises); service methods same; controller
  handlers may stay sync or wrap in async — Hono accepts both. Do not introduce
  `Promise.resolve(...)` wrappers just to match pty's async style; the ADR's "service
  stays framework-free" rule does not mandate async.
- **Run `pnpm --filter @repo/server db:generate` after editing any file under
      `packages/server/src/db/schema/`.** Always commit the generated SQL alongside the
      schema change (matches existing convention).
- **`migrate.ts` path resolution must survive bundling.** The banner in
  `apps/server/tsup.config.ts:15` injects `createRequire`/`import.meta.url` shims — keep
  using `fileURLToPath(import.meta.url)` for `__dirname`. If migrations fail to load in the
  bundled binary, check that `scripts/copy-assets.ts` copied `packages/server/drizzle/` →
  `apps/server/dist/drizzle/` and that the resolved `__dirname/../../drizzle` lands there.
- **Do not add `instanceId`** to the schema, model, or DTO — it is dead on the frontend and
  will be dropped in the follow-up frontend plan.
- **Frontend is out of scope.** Do not touch `apps/web-app/src/stores/workspaceStore.ts`
  or any frontend consumer. The follow-up frontend plan will replace the Zustand store
  with React Query hitting the new `/api/workspaces` endpoints.
- **Don't commit `.env*`, `dist/`, or `*.tgz`.** No commit unless explicitly asked.
